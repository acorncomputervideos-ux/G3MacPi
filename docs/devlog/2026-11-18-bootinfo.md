# 2026-11-18 — CHRP bootinfo parser

- Found and read the CHRP binding (rev 1.7, §3.1.6), which defines the
  bootinfo format at the start of Mac OS's boot file.
- `of::parse_bootinfo`: elements, case-insensitive tags, skipped unknown
  elements, several sections, entities (path entities only in the boot
  script), icons with defaults, and the offset of the binary data that
  follows.
- Sabotage: 11 mutations. Two first survived (an end tag that only starts
  with the element's name, and spaces around `=`); the tests added for
  them found a real bug (spaces before `,` in attributes), now fixed. All
  are caught now.
- 194/194 tests pass. Next: the Forth engine that runs the boot script.

## Same day: the Forth interpreter, language core

- `forth::Forth`, written from ANS Forth plus IEEE 1275's differences:
  - stacks, arithmetic and logic;
  - guest-memory data space;
  - colon definitions;
  - if/else, begin/until/while/repeat/again, do/?do/loop/+loop/leave,
    case/of;
  - variable/constant/value/to, create/does>, defer/is, immediate;
  - strings with hex escapes, number prefixes, output words;
  - evaluate, catch/throw, abort";
  - native words from C++.
- Five failures in the first run were all mistakes in my test
  expectations (e.g. typing `5` while the base was binary); fixed in the
  tests, not the code.
- Sabotage: 15 mutations. Removing the cleanup of a failed definition
  can't be observed (the word stays hidden), which is documented. The
  nesting limit is required: without it ASan reports a host stack
  overflow.
- 202/202 tests pass.

## Same day: boot, init-program, go

- `boot` = load + init-program (+ go). A bootinfo object's script runs
  with path entities; an ELF is prepared and started through a `go`
  callback. `Forth::evaluate` runs host text nested inside a native word.
- The chain test (a boot script that loads and starts an ELF) found a
  real bug: `boot` called `go` a second time after the script had
  already done so. The fix needed two attempts, because the script's
  own `init-program` cleared the flag; it is now set after the script
  returns.
- Sabotage: 6 mutations, all caught. 213/213 tests pass.

## Same day: interpret and call-method

- The `interpret` and `call-method` client services run through the
  Forth interpreter. The stack order (arg1 on top, ret1 = top) is taken
  from how Linux's prom_init calls the `color!` and `claim` methods,
  whose Forth stack effects are known.
- New words: `reg`, `my-self`, `ihandle>phandle`. The test runs Linux's
  own node-building snippet (adapted to our tree), which uses
  `my-self ihandle>phandle` to get a new node's phandle.
- Sabotage: 7 mutations, all caught. 216/216 tests pass.
