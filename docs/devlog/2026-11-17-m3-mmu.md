# 2026-11-17 — Milestone 3 step 1: MMU

- `core/cpu/ppc750/ppc750_mmu.cpp`: BAT translation, segment registers,
  hashed page table walk with primary/secondary hash and HTABMASK, R/C bit
  updates, protection (PP with Ks/Kp; BAT PP), no-execute and guarded
  fetches, DSI/ISI with cause bits. All data accesses, instruction fetches,
  lwarx/stwcx. (physical reservation) go through it; page-crossing accesses
  are translated completely before any byte is written.
- 14 new tests; page-table addresses computed by hand in the test comments.
  Sabotage checks (HTABMASK ignored, C bit not set, Ks/Kp swapped) are each
  caught by a test.
- 97/97 tests (gcc + ASan/UBSan, clang); check-core passes.

## Performance findings (measured, see docs/hardware/ppc750-cpu.md)
- Real mode got ~20 % slower: the uncached translation hooks plus
  `execute()` no longer being inlined (callgrind: +21 % host instructions).
  Forcing inline was tried and made it worse — reverted.
- Page-table mode: ~43 M guest instr/s vs ~90 M BAT-mapped: a soft TLB is
  the obvious next step and can be verified against the uncached path.

## Step 2: soft TLB
- Direct-mapped I/D translation caches with hardware-like invalidation.
- Page-table-mapped benchmark: ~43 M -> 73-93 M guest instr/s.
- Two existing tests poked BAT/PTE state directly from C++; they now flush
  the TLB at exactly the point where real software would execute
  mtspr/tlbie (a real 750 would also keep the old translation).
- New: 4 TLB unit tests (stale entry until tlbie; flush on mtsr/mtspr; C bit
  set by a store after a cached read; user/supervisor separation) and a
  differential test (TLB vs uncached, 200,000 random steps, registers +
  memory + page table compared after every instruction): 0 mismatches.
- Sabotage: dropping the C-bit condition or the PR tag bit is caught by both
  the differential test and a targeted unit test.
- 102/102 tests (gcc + ASan/UBSan, clang); check-core passes.
