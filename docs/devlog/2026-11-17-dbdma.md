# 2026-11-17 — DBDMA controller

- New `DbdmaController` (16 channels) with descriptor execution: data
  transfers, LOAD/STORE_WORD, NOP, STOP/WAKE, and the interrupt, branch and
  wait conditions. A channel goes DEAD on an invalid descriptor.
- Mapped into Paddington at BAR + 0x8000 (QEMU Old World layout; to verify).
- Fixed a latent bug in Paddington's mapping: when a cell conflicted with
  another bus region, the rollback also unmapped that *other* region. Only
  the cells actually mapped are now removed, and a test covers it.
- Tests drive the controller the way Linux does (`out_le32`, little-endian
  descriptors, the DO_STOP and DO_RESET sequences, appending work with
  STOP+WAKE).
- Sabotage runs (no BT, no advance, no status write-back, wrong interrupt
  condition, no FLUSH acknowledge, DEAD not cleared, LOAD_WORD byte order,
  rollback that unmaps everything) are all caught. Two of them first went
  unnoticed (the status write-back and the FLUSH acknowledge), so those
  tests were tightened.
  Retrying a device that isn't ready differs only in wasted loop iterations;
  no test can see it.
- 154/154 tests pass.

## Correction (same day)

While researching IDE I found that the 0x100 channel stride had no source.
QEMU defines the stride as 0x80 (`DBDMA_CHANNEL_SHIFT` 7, so 32 channels
in the 0x1000 window) and places IDE0's channel at 0x16, i.e. BAR + 0x8B00.
Linux's register block is 0x40 bytes, which fits. The model and the docs
are fixed, and the machine test now uses channel 0x16 at BAR + 0x8B00.
Lesson: every constant needs a cited source, including the "obvious" ones.
