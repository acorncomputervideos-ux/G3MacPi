# 2026-11-17 — Milestone 2b: floating-point unit

## New
- `core/fpu/ieee754.*`: software IEEE 754 arithmetic (add, sub, mul, div,
  fused multiply-add, sqrt, round-to-single, to-int32, single<->double bit
  conversions) with all status flags incl. PowerPC FR.
- `core/cpu/ppc750/ppc750_fpu.cpp`: every 750 FP instruction, FPSCR
  semantics, FP loads/stores, FP exceptions.

## Verified (Linux container + CI-equivalent clean builds)
- **All 2054 FP vectors and all 5620 integer vectors pass** (the DingusPPC
  emulator itself fails 448 of the FP vectors).
- IEEE core vs host FPU: ~2.2 million random cases, all modes, bit-exact
  results and identical flags.
- Sabotage checks: breaking round-half-even, the underflow rule, zero-sum
  sign (IEEE core) and the SNaN flag / FPRF class (PowerPC layer) each made
  the tests fail; restored code passes.
- 80/80 tests with gcc + ASan/UBSan and with clang; freestanding AArch64
  compile passes; the 128-bit division helpers the core needs exist in the
  Pi toolchain's libgcc.

## What the vectors taught us (initially 40 failures)
1. FR on overflow is set exactly when significand rounding increments.
2. Single-precision multiplies shorten frC before multiplying (rule inferred,
   see docs/hardware/ppc750-cpu.md — needs confirmation on a real 750).

## Open questions for real hardware (no action needed now)
Tininess detection, the exact frC shortening rule, fres/frsqrte estimate
bits, undefined high words of fctiw/mffs.
