All three fixes from test 1 confirmed on hardware:

- Circle's timer calibration `SpeedFactor` went from 1.51 to 4.54
  (≈3×, consistent with 600 → 1800 MHz).

## New in this step
- `core/common/spsc_queue.h`: lock-free single-producer/single-consumer
  queue (USB interrupt → main loop now; between cores later).
- `platform/common/input_events.h`: host input event types, independent of Circle.
- `platform/common/hid_keyboard.*`: turns USB HID boot reports (modifier
  byte + 6 key slots) into individual press/release events — the form the
  emulated ADB keyboard will need. Ignores rollover-error reports; releases
  before presses; `release_all()` when a keyboard is unplugged.
- Kernel: USB plug-and-play, raw keyboard + mouse handlers that only queue
  events in interrupt context, on-screen event log, mouse movement summarised
  at most 5×/s, Ctrl+Alt+Delete reboot, `CCPUThrottle::Update()` every 2 s,
  `wfi` when idle.
- SD card: FatFs mount, `SD:/g3macpi/logs/boot.log` written after startup
  and before reboot; previous run kept as `boot-prev.log`.
- Pi build now uses `-Wall -Werror` for our code.

## Bug found and fixed: Circle macro clash
Circle's `<circle/util.h>` `#define`s `bswap16`/`bswap32` to the compiler
builtins. Our `g3::bswap32` was silently renamed to
`g3::__builtin_bswap32` and became a self-recursive function. GCC reported it
only as a warning (`-Winfinite-recursion`). Renamed ours to `byteswap16/32/64`
and made warnings fatal in the Pi build. The M0 self-test had passed because
the call was evaluated at compile time.
