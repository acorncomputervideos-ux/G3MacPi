# CMD646U2 PCI Ultra ATA controller (the B&W's hard-disk bus)

Code: `core/devices/ata/cmd646.*`; wired in `core/machine/yosemite.*`
(PCI 01:01.0 behind the DEC bridge, INTA to Paddington input 26); BARs
assigned in `core/machine/bw_firmware.cpp`; device-tree node in
`core/firmware/openfirm/bw_device_tree.cpp`. Tests:
`tests/unit/devices/test_cmd646.cpp`, `tests/unit/firmware/test_bw_device_tree.cpp`
(sabotage runs caught W1C, interrupt blocking, end-of-table, I/O enable,
the bridge ranges and the channel's compatible).

## Sources

- Real Blue & White: Linux `lspci` / boot log (tomari's gist):
  `01:01.0 IDE interface: Silicon Image, Inc. PCI0646 (rev 07) (prog-if 8f)`,
  "pin A routed to IRQ 26", `ata1: PATA max UDMA/33 cmd 0x1440 ctl 0x1430
  bmdma 0x1400 irq 26`, secondary port disabled. Users' boot paths:
  `/pci@80000000/pci-bridge@d/pci-ata@1/ata-4@0/@0`.
- PCI IDE Controller Specification 1.0 (BAR layout, control block at +2)
  and SFF-8038i (bus master command/status/PRD registers and PRD format).
- DingusPPC's CmdIdeCtrl and Yosemite machine (facts only): class 0x01018F,
  revision 7, BAR sizes, MRDMODE at bus master +1 (interrupt flags W1C,
  block bits), UDIDETCR0 at +3, interrupt source 0x1A.
- OpenBIOS: the Grackle host node's model "MOT,MPC106".

## Model

- Configuration: IDs 1095:0646, class 01 01 8F, five I/O BARs (8, 4, 8, 4,
  16 bytes), interrupt pin A; 0x40-0x7F stored (MRDMODE mirrored at 0x71).
- I/O windows are mapped at 0xFE000000 + BAR (Grackle's PCI I/O space)
  while I/O decoding is on.
- Taskfile: two AtaBus channels (shared with the mac-io controller and
  the ATAPI CD-ROM): command block at BAR0/2, alternate status / device
  control at BAR1/3 + 2.
- Bus master: start/direction, status (active, error and interrupt W1C,
  drive-capable bits), PRD pointer; PRD tables are read from guest RAM.
  A table pointing outside RAM sets the error bit.
- Interrupt: each channel's INTRQ, unless blocked in MRDMODE, drives INTA.

## What Mac OS needs

Mac OS 9's ROM driver "cmd646-ata" (a PEF in the Mac OS ROM file; found by
disassembly and by watching it run):

1. It binds to the channel node `ata-4` (compatible "cmd646-ata"), not to
   `pci-ata`. With `device_type "ata"` on `pci-ata` instead it fails early.
2. It writes the registers at `AAPL,address`, which Mac OS computes from
   `assigned-addresses` through the parents' `ranges`. The PCI-to-PCI
   bridge node needs `ranges` for that: without them the addresses stayed
   bare port numbers (0x1430) and the driver wrote to RAM. The firmware
   programs the same windows into the bridge (I/O 0x1000-0x1FFF, memory
   around mac-io).
3. With both, it sends IDENTIFY DEVICE, INITIALIZE DEVICE PARAMETERS and
   READ SECTORS (the driver descriptor map) and enables interrupt 26.

Mounting a hard disk still needs Apple's ATA driver on the disk
(docs/storage/disk-format.md).
